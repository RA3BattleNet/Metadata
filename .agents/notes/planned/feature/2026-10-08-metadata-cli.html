让 Modder 的 agent 管理模组

扩充现有 Metadata CLI：添加模组、导入版本清单、编辑样式与 Markdown 介绍、内置 Web 可视化预览、创建 PR；用配套 skill 串起整个操作流程。

主要使用者是 Modder 的 agent。CLI 提供可验证的操作，Web Studio 提供可视化编辑与预览，二者共用同一套源文件读写逻辑。Modder 也可以不使用 agent，直接启动 Studio。

范围与已确认决定

  • 只先做 Metadata 侧。本轮交付计划并提交推送；未来实现也不以修改 Desktop 为前置条件。
  • 内置本地 Web。不是只输出截图或打开静态 XML；支持表单编辑、Markdown 编辑、图片选择、预览、差异检查和保存。
  • 介绍使用 Markdown。作为模组独立介绍，不借用新闻的 Post.Descriptions 或 Posts；Desktop 最终另行增加 Markdown 渲染。
  • 更新模组＝导入真实 Manifest + 更新版本元数据。不生成文件哈希，不打包或上传安装文件，不替代 Updater。
  • 不新增新闻相关功能，也不新增 DLL 注入功能。现有 Posts、Dependencies 以及其他未编辑节点原样保留；不提供新闻编辑页面、命令或注入配置。
  • 提交 PR 前展示差异并取得明确授权。不自动合并，不绕过审核；本轮只推送计划分支，不自动创建计划 PR。

上述范围来自用户确认。后文的命令名、Introductions 字段名、项目拆分和打包方式是本计划建议，不是现有 API，也不是已经实施的功能。没有虚构负责人、工期、完成率。

术语本计划的含义
模组拥有全仓库唯一 ID、显示名、样式、版本包和独立介绍的 Mod 实体。
版本更新登记一个已有真实安装清单的版本，可同时设为 CurrentVersion；不是下载、安装或发布二进制文件。
模组介绍按语言登记的 Markdown 正文，描述模组本身；不是公告摘要、版本更新日志。
预览根据候选源树 Build 后的有效样式、资源与介绍渲染；原始声明和继承后结果分开展示。
保存 / 提交保存只写本地源文件；Git 提交、推送和创建 PR 是另一项明确授权的操作。

建议的介绍契约

Mod 下新增可选 Introductions，置于 DisplayName 之后、Style 之前；容器出现时至少一项。Introduction@Language 使用完整语言标签，文本引用已登记的 Markdown 短 ID。介绍属于实体自身，不从 Base 继承，不扩展 Application 的介绍功能。

<Metadata>
  <Markdown ID="intro-zh" Source="introductions/zh-CN.md" />
  <Markdown ID="intro-en" Source="introductions/en-US.md" />
  <Mod ID="ExampleMod">
    <DisplayName Language="zh-CN">示例模组</DisplayName>
    <DisplayName Language="en-US">Example Mod</DisplayName>
    <Introductions>
      <Introduction Language="zh-CN">intro-zh</Introduction>
      <Introduction Language="en-US">intro-en</Introduction>
    </Introductions>
    <Posts />
  </Mod>
</Metadata>

上面是介绍字段的最小合法结构示意，不是可安装版本示例；不包含占位 Manifest。

  • 同步更新源/发布 XSD 与 IsTextReference。在 ValidateHard 新增仅包含 Markdown 登记的 markdownIds 索引校验 Introduction，不能使用混合 Image/Markdown/Manifest 的 idIndex。空语言/引用、不存在的 ID、Image/Manifest 类型误用必须失败。
  • XSD 表达结构与“容器出现则至少一项”；大小写不敏感的语言去重在 ValidateHard 实现，不能只依赖大小写敏感的 xs:unique。将 Introductions 明确加入 MetadataInheritance.ModChildOrder 的 DisplayName 与 Style 之间，并保证只取当前 Mod 的介绍；否则继承合并可能把节点追加到错误位置。
  • 介绍契约同步更新模板、README.md 和作为贡献者入口的 AGENTS.md；这些是未来实施改动，本轮不修改。
  • 沿用 SchemaVersion=1.0 的现有政策，明确旧客户端忽略介绍不等于已支持介绍。Library 提供 Mod 介绍枚举/精确语言查询；预览精确匹配，未命中取 XML 第一项，并显示所选语言。Desktop 后续消费应明确采用同一规则。
  • 无介绍就不写该节点；不强制制造英译，不从正文自动截取简介。现有 Mod 无需批量填空介绍。
  • Markdown 的相对图片路径以该 Markdown 文件目录为基准。资源图片登记为 Image，Build 扩充介绍资源复制/路径校验：本地引用必须命中登记资源且在模块内；复制后路径保持可解析。避免源文件里能看、发布目录里丢图。HTTP/HTTPS 外链不自动下载；预览默认提示并由用户允许加载。

写入规则

  • 沿实际 Include 树定位实体文件和资源声明文件，保留来源映射；不能编辑展平结果再反向覆盖源 XML。实体 ID 与目录名不能假定完全一致。
  • 原始声明、继承有效值与主题缺省值分开；清空字段＝移除本地声明，不删除公共 Base、不把预览主题写入 XML。编辑继承 Logo/Background 时明确提示整项覆盖。
  • 先构造候选变更，在自有临时工作副本中复用 Build，验证通过后才写入目标。保留 XML 注释、未知未编辑节点、Posts、清单内容与其他 Mod；避免全文件格式化。
  • 多文件保存不是天然原子操作：先校验与检测外部修改，再逐文件替换；失败回滚已写入文件，报告失败文件。保存前发现源文件已变更则拒绝覆盖并要求重新载入。
  • 严格限制可写目录；拒绝路径穿越、越界 Include、符号链接/目录联接逃逸。只更新当前命令拥有的文件，不修补其他模块。

命令输入与职责改动 / 输出
build / validatebuild 保留现有参数；validate 无需用户指定输出，调用完整 Build 到工具临时目录。validate 不改源树/已有 Output；报告文件、节点、原因，非零退出。
mod list / mod show <id>列目录；show 给来源文件、本地声明、有效样式、版本和介绍引用。只读；agent 不需自己拼限定 ID。

mod update <id> --version V --manifest file.xml --set-current导入一个明确目标 Manifest 的叶子 XML，可选 ReleaseDate；多 Manifest 输入需指定 ID。叶子清单、manifests.xml、Packages，显式设置时才改 CurrentVersion；保留旧版本。
mod style <id> --input style.json结构化字段补丁，支持 null 移除声明；颜色值与 Format 为一项。仅当前 Mod.Style。新增本地图片可通过 mod asset 登记。
mod asset <id> --id image-id --file image.png导入图片到当前模块 images 并登记短 ID；显式改现有资源，不静默覆盖。资源登记与图片文件；无需生成图片 Hash。
mod intro <id> --language zh-CN --file intro.md导入/更新一个语言的 Markdown；与可选 --remove-language 互斥。introductions/*.md、Markdown 登记、Introductions；不修改 Posts。
studio --mod <id> --no-open启动内置 Web；默认打开浏览器，agent 可禁止自动打开并获取会话地址。长期服务。表单编辑/预览/保存；启动本身不写源数据、不提交 Git。
pr prepare / pr create --confirm指定 base/head、目标上游、模组和变更文件；prepare 仅生成差异/正文，create 执行被授权的提交推送与 PR。可审查提交、远程分支、PR URL；默认草稿，不自动合并。
agent 的机器契约

JSON 单个响应建议包含 ok、command、modId、changedFiles、diff、diagnostics；诊断有 code/file/node/message，可获得时补 line/column。stdout 只放 JSON，日志走 stderr。帮助与输入 JSON schema 随工具发布。

退出码建议：0 成功；2 命令/输入错误；3 数据校验失败；4 外部改动冲突；5 Git/GitHub 操作失败。非交互场景缺信息立即报错，不挂起等输入。dry-run 给出相同候选差异和完整校验结果，但不修改仓库、Git index 或远程。

版本导入的具体边界

先完整校验清单 HashAlgorithm、真实文件哈希、Source 与 Skudef 挂载引用，不重算、不重命名内部 FileName，不改变加载顺序。导入前检查该 Mod 的 Include 作用域内 Manifest 短 ID 唯一，重名时列出冲突叶子文件；避免 Package 的短引用变得歧义。相同版本/目标路径已存在时拒绝覆盖；重复执行同样导入可报告无变化，但不能创建重复 Package 或 Include。默认每次导入保留历史；更改 CurrentVersion 必须指向现存的有效版本，版本字符串不擅自按 SemVer 排序。

内置 Web Studio

采用现有 Studio 的“编辑面板 + 预览区”交互，但从 CLI 所选工作树读真实数据。Web 保存调用与 CLI 相同的候选变更服务，禁止另写一套 XML 编辑器。

界面区域必须可操作预览与边界
模组 / 版本选择、添加 Mod；中英显示名；导入 Manifest、登记版本、显式设为当前版。展示真实清单检查结果，不模拟下载/安装。
控件样式Primary/Secondary Label、Button；字号、字重、颜色、边框；普通/Hover/Active。Active 不回退 Hover；颜色按 CSS/ARGB；0 值与缺省区别。
布局 / 图片Logo 宽高、九宫格、偏移；背景列表、Random、Color/SecondaryColor；导入图片和引用。单边尺寸保比例、多图手动切换、缺失资源错误；Inherited 与 local 标识清楚。
模组介绍语言选择、Markdown 编辑、图片插入、并排正文预览。使用真实文档；不展示虚构新闻。精确语言回退可见，草稿与已保存状态分开。
检查 / 保存候选变更差异、完整校验结果、保存和放弃草稿。无效草稿可暂存于会话但不能写源；保存后重载验证结果。
PR显示目标上游/base/head、提交文件和正文；明确授权后发起。不会因编辑、预览或关闭窗口而自动推送。

渲染真实性

  • 有效数据由 C# Build/Load 得到；颜色只在服务端经 MetadataColor.ToCss 转换一次，Web 不另做 ARGB 转换，后端不补主题值。布局/状态映射是 Studio 自有实现，语义基线为 Desktop mod-style.ts:13–47；记录来源版本，以相同状态/布局场景检查漂移，不直接导入 Desktop 工程。
  • 预览明确显示“Metadata Studio 参考渲染；Desktop 的介绍渲染尚未接入”。当前页框架、磨砂、卡片间距属于 Studio 主题，不能成为 XML 配置字段。
  • 提供浅/深主题、桌面/窄宽、按钮真实交互/强制三态、背景切换；以真实名称和介绍检查，不从旧 Studio 拷贝演示文章。
  • 本地资源通过专用 asset route 使用资源 ID 映射到许可文件，不开放任意路径读取。外链默认不加载；点击链接在用户确认后打开 HTTP/HTTPS 外部浏览器。

预览构建使用每次请求唯一的临时 dst，同一会话串行 Build；成功后才替换当前预览快照。Build 校验整棵源树，无关 Mod 的错误也会阻塞预览，必须展示真实失败文件，不能绕过该校验。Markdown 引用与文件校验明确扩展 ValidateHard，不将未参与 Build 的旧校验辅助代码当作现成入口。

宿主、依赖与安全

建议增加独立 Ra3.BattleNet.Metadata.Studio 可执行项目：引用主项目中的纯 managed 编辑服务，使用 ASP.NET Core/Kestrel 承载内嵌构建后的 Web 资源。原 NuGet 解析包不引用 ASP.NET Core、Vue 或 SkiaSharp；原 CLI 的 studio 子命令启动随安装包交付的 Studio 进程。开发环境用 .NET 10，前端建议 Vue 3，与参考工具/客户端一致；具体依赖版本在实施时按锁文件和官方文档确定。

  • 只监听 127.0.0.1，默认动态端口；Kestrel 用显式 loopback 地址，不用不支持端口 0 的 ListenLocalhost。Ctrl+C 关闭子进程和会话；浏览器关闭不等于进程退出。
  • 会话初始化后用受保护 cookie/请求校验建立权限；校验 Host、Origin 和会话写入凭证，拒绝跨域写入及 DNS rebinding。不会将访问凭证、GitHub Token、环境变量写入日志或元数据。
  • Markdown 在渲染后净化 HTML，限制 URL 协议；不执行内嵌脚本/事件、不加载任意 iframe。导入 XML 禁用 DTD/外部实体；拒绝路径穿越和链接逃逸。上传只接受本工具需要的资源类型和合理大小。
  • 前端静态资源和运行库随包交付，无 CDN、无首启联网下载；普通 Modder 不需要 npm 或 Desktop 安装。建议首个安装产物为自包含 win-x64 包，包含 CLI、Studio、XSD、模板、skill 和许可证；其他平台仅在真实构建/烟测后声明支持。
  • 分发装配与更新沿仓库现有构建入口补齐，不创建依赖 Desktop 的循环构建。打包后在不安装 SDK/npm 的 Windows 环境实际启动 CLI 和 Studio，验证不是只在源码目录能运行。

PR 的权限和副作用

  • 本地仓库必须已有正确上游；解析 remote 时不打印含凭据的 URL。有写权限推当前工作分支；无权限通过 gh 建立/复用个人 fork，说明需要 Git 与 gh 的已有登录。
  • base 默认取上游默认分支；不提交到默认分支，不强推。使用明确 --repo/--base/--head，阻止 gh 交互式意外 fork/push；目标与改动列表在 prepare 中可审查。
  • gh 官方文档明确 gh pr create --dry-run 仍可能推送。CLI 的 prepare/dry-run 必须自行只读实现，不能直接透传这个选项。
  • 操作失败报告最后成功步骤及现存提交/分支；不自动删除远程分支或回退用户 Git 状态。再次创建前按 repo/head/base 查已有 PR；不做未经授权的重试发布。
