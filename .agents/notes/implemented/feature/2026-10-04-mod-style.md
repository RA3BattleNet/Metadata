# Agent Note: Mod 页面自定义样式

Status: implemented

本记录中的样式字段、颜色与继承规则继续有效；升级为 `2.0` 的决定已被 [保持元数据版本 1.0](2026-10-04-metadata-schema-version.md) 取代。当前默认发布版本为 `1.0`，下文 `2.0` 与对应验证结果保留为当时实施记录。

## Problem

修改前，本仓库中的元数据清单（`metadata.xml`）已经包含 `<Style>` 节点，但在实际使用与规范约束中存在以下问题：
1. **分类与字段缺乏明确结构与校验**：修改前 `MetadataSchema.xsd` 中，`Controls` 使用了 `<xs:any processContents="lax"/>`，没有明确声明允许出现的子控件、颜色格式和状态节点；构建校验层（`MetadataBuilder.cs`）仅校验了 Logo 和 Background 所引用的图片 ID 是否在顶层登记，缺乏对控件名称、字号、字重、边框宽度、颜色格式与长度的校验。
2. **颜色编码格式未定导致歧义**：历史遗留配置存在 8 位十六进制颜色串，消费端无法判断是现代 Web 规范的 `#RRGGBBAA`（CSS Hex8）还是传统桌面客户端的 `#AARRGGBB`（ARGB），容易导致红色与透明度通道解析颠倒。
3. **交互状态缺乏明确层级与继承定义**：按钮存在悬停（Hover）与按下（Active）状态。修改前定义没有明确 Active 与 Hover 的独立性，可能导致按下状态错误继承悬停状态的背景色，或在鼠标释放后无法正确回落到基础状态。
4. **旧命名与现代前端标准脱节**：旧定义中使用了部分桌面端专属称谓（如 `LaunchButton`、`Label`、`Brush`、`Thickness`、`IsBold`）。本次需要统一规范，彻底废弃旧名称，不保留兼容别名。
5. **版本兼容性要求**：现有的通用元数据解析器并不会自动校验 Schema 约束或阻断未知字段，但库内的版本兼容辅助工具在将 `MetadataSchema.Current` 与 `MetadataBuilder.DefaultSchemaVersion` 提升为 2.0 后，其兼容性检查方法（如 `IsCompatible`）面对 1.0 的数据将返回 `false`（加载器本身仍是通用宽松解析），客户端必须显式检查版本以确保契约匹配。因此需要把 SchemaVersion 升级为 2.0。

需要说明的是：本仓库（Ra3.BattleNet.Metadata）是 C# 元数据解析、构建与 Schema 定义仓库，不是桌面端前端渲染代码库。本仓库只负责定义数据协议、XML 序列化/反序列化及合规性校验。未来在 Vue 客户端消费端渲染时，计划通过客户端主题样式与预设的毛玻璃遮罩（backdrop-filter）展示背景层次，元数据本身不提供页面级透明度（Opacity）或模糊半径（BlurRadius）等冗余字段。

## Decision

本规范正式确立了 `<Style>` 下属所有节点、子元素及 XML 属性的完整规范，统一采用 XML PascalCase 规范，定义颜色格式与分层合并规则。

### 1. 核心设计原则

1. **协议层与未来渲染端的分工**：
   - 元数据只提供纯粹的数据定义（颜色、字号、字重、尺寸、偏移、九宫格锚点、图片短 ID 引用）。
   - 不包含页面级 `Opacity` 或 `BlurRadius` 字段，透明度通过各颜色节点的 Alpha 通道表达。在未来的 Vue 桌面端中，半透明底色可结合主题预设的磨砂效果渲染，文字与按钮保持正常展示。
2. **全可选与无 XSD 默认值**：
   - `<Style>` 节点本身、下属的 `Logo`、`Controls`、`Background` 分类、内部每个控件、状态以及各属性字段均为可选，也允许出现空的 `<Style/>` 或空的分类节点。
   - XSD Schema 中不设置任何内建默认值，防止在未配置时产生污染。所有缺省字段由客户端消费端按预设兜底。
3. **分类与字段的继承与合并规则**：
   - **元数据层只负责原始字段合并**：元数据层（`MetadataInheritance.cs`）只将 Base 与子级的声明字段进行合并，并不在 C# 对象中补齐或展开缺省状态的默认值；缺失状态（例如未声明 Hover 或 Active）的最终回退由消费端（如 Vue 渲染层）负责处理。
   - **Logo 与 Background**：遵循现有的“整分类替换”原则。如果 Mod 配置了 `Logo`（或 `Background`），则整项完全覆盖；如果未配置，若声明了 `InheritFrom` 则完整继承 Base 对应分类；如果均未配置，则由客户端主题默认值呈现。
   - **Controls**：遵循“分层字段合并”原则。当 Mod 继承 Base 时，合并 Base 与 Mod 的控件。
   - **Active 状态语义**：Active 代表鼠标按下（Pressed），不是选中（Selected）。Active 状态独立声明或由消费端回退至基础状态，绝对不会自动继承 Hover 状态的特有属性；当鼠标释放时，界面根据鼠标当前所处位置准确返回 Hover 或基础状态。
4. **颜色值与 Format 一起替换**：
   - 每个颜色节点都是子元素，且支持可选的 `Format` XML 属性，取值为 `CSS` 或 `ARGB`。未传 `Format` 属性时默认为 `CSS`（若传入空字符串属于非法格式）。
   - 当 `Format="CSS"` 时，颜色值支持 `#RRGGBB`（6 位）与 `#RRGGBBAA`（8 位）。
   - 当 `Format="ARGB"` 时，颜色值仅支持 `#AARRGGBB`（8 位）。
   - 继承合并时，颜色值和 Format 一起替换，不单独继承原先声明的 Format。校验器在构建与发布期根据声明的 Format 严格比对字符串长度与字符合法性。
5. **单位、零值与缺省判断**：
   - 正数数值字段（如 Width / Height / FontSize）使用有限正十进制数（positive decimal，不接受无穷大或 NaN）；边框宽度（BorderWidth）为非负十进制数（>= 0）；偏移量（OffsetX / OffsetY）使用带符号十进制数（signed decimal）。单位均为逻辑像素（px）。
   - 显式声明的 0（如 `OffsetX="0"` 或 `<BorderWidth>0</BorderWidth>`）属于有效配置，必须完整保留，不能被当作缺省丢弃。
   - 单边尺寸缺省时（例如只提供了 Width 未提供 Height），由消费端按图片原始比例自动计算未设置的一边。

### 2. 节点与属性列表

本规范下所有节点、子元素及 XML 属性定义如下：

#### (1) 顶层图片登记与 Mod 结构
- 原始源文件根节点为 `<Metadata>`（不写 `SchemaVersion` 与 `ContentRevision`，构建工具发布时会自动注入这些属性并转换限定 ID）。
- 顶层图片通过平铺的 `<Image ID="..." Url="..."/>` 进行登记（无 `<Images>` 包裹节点）。
- Mod 定义在 `<Mod ID="...">` 节点中，内部包含可选的 `<Style>` 节点。Mod 名称使用 `<DisplayName Language="...">` 声明在 `<CurrentVersion>` 之后。

#### (2) Logo 分类（`<Logo>`）
用于配置 Mod 详情页的标志展示。
- **节点文本内容**：引用的图片登记短 ID（例如 `corona-banner`），对应顶层登记的 `<Image ID="corona-banner" .../>`。
- **属性**：
  - `Width`（可选，正十进制数）：Logo 的显示宽度（逻辑像素）。缺省且设置了 Height 时，按图片原始比例缩放。
  - `Height`（可选，正十进制数）：Logo 的显示高度（逻辑像素）。缺省且设置了 Width 时，按图片原始比例缩放。
  - `Position`（可选，枚举）：Logo 在指定区域内的九宫格停靠锚点，共有 9 种取值：
    - `TopLeft`（左上角）
    - `TopCenter`（顶部居中）
    - `TopRight`（右上角）
    - `CenterLeft`（垂直居中靠左）
    - `Center`（绝对居中）
    - `CenterRight`（垂直居中靠右）
    - `BottomLeft`（左下角）
    - `BottomCenter`（底部居中）
    - `BottomRight`（右下角）
  - `OffsetX`（可选，带符号十进制数）：相对于选定锚点的水平偏移量（逻辑像素），正数向右，负数向左。允许为 0 并保留。
  - `OffsetY`（可选，带符号十进制数）：相对于选定锚点的垂直偏移量（逻辑像素），正数向下，负数向上。允许为 0 并保留。

#### (3) Controls 分类（`<Controls>`）
包含详情页主/次文本标签与主/次按钮的样式配置。

##### A. 文本标签（`<PrimaryLabel>` 与 `<SecondaryLabel>`）
- `<PrimaryLabel>`（可选）：主标题与主文本标签样式。
- `<SecondaryLabel>`（可选）：副标题与辅助说明标签样式。
每个标签节点下包含以下可选子元素：
- `<Color>`（子元素，可选）：文本前景色。文本内容为十六进制颜色字符串。可选属性 `Format`（枚举，取值 `CSS` 或 `ARGB`，未传时默认为 `CSS`）。
- `<FontSize>`（子元素，可选）：正十进制数，文本字体大小（逻辑像素）。
- `<FontWeight>`（子元素，可选）：100 到 900 之间的任意整数（如 400 为常规，700 为粗体），定义字体粗细。

##### B. 按钮（`<PrimaryButton>` 与 `<SecondaryButton>`）
- `<PrimaryButton>`（可选）：主操作/启动游戏按钮样式。
- `<SecondaryButton>`（可选）：次要操作按钮（如配置设置、打开目录）样式。

按钮基础元素直接设置基础状态（Base）下的样式，同时可包含两个可选子状态节点：
- `<Hover>`（子元素，可选）：鼠标悬停时的样式。
- `<Active>`（子元素，可选）：鼠标按下时的样式。

按钮基础样式及其 `<Hover>`、`<Active>` 子状态中，均可包含以下可选子元素：
- `<BackgroundColor>`（子元素，可选）：按钮背景填充颜色。包含可选属性 `Format`（`CSS` 或 `ARGB`，未传时默认为 `CSS`）。
- `<BorderColor>`（子元素，可选）：按钮边框线条颜色。包含可选属性 `Format`（`CSS` 或 `ARGB`，未传时默认为 `CSS`）。
- `<BorderWidth>`（子元素，可选）：非负十进制数（>= 0），边框宽度（逻辑像素）。允许为 0（无边框）。
- `<Color>`（子元素，可选）：按钮内部文本前景色。包含可选属性 `Format`（`CSS` 或 `ARGB`，未传时默认为 `CSS`）。
- `<FontSize>`（子元素，可选）：正十进制数，按钮文字大小（逻辑像素）。
- `<FontWeight>`（子元素，可选）：100 到 900 之间的任意整数，定义按钮文字粗细。

#### (4) Background 分类（`<Background>`）
用于配置 Mod 详情页的背景图集与底色。Schema 顺序为：先 `<Image>` 列表，后 `<Color>` 与 `<SecondaryColor>`。
- **属性**：
  - `Random`（可选，布尔值）：取值 `true` 或 `false`。当包含多张背景图时，客户端是否在进入页面时随机挑选一张展示。
- **子元素**：
  - `<Image>`（多值子元素，可选）：引用的背景图片短 ID。节点文本为顶层登记的 `<Image ID="..." Url="..."/>` 的 ID（纯文本引用，无 Id 属性别名）。
  - `<Color>`（子元素，可选）：页面背景底色。包含可选属性 `Format`（`CSS` 或 `ARGB`，未传时默认为 `CSS`）。若包含 Alpha 透明通道，透出客户端主题预设的磨砂背景。
  - `<SecondaryColor>`（子元素，可选）：内容卡片底色（Card Background）。包含可选属性 `Format`（`CSS` 或 `ARGB`，未传时默认为 `CSS`）。

### 3. XML 示例

```xml
<?xml version="1.0" encoding="utf-8"?>
<Metadata>
  <!-- 顶层直接登记图片，平铺放置无 Images 包装节点 -->
  <Image ID="corona-banner" Url="https://cdn.example.com/corona/banner.png" />
  <Image ID="bg-main" Url="https://cdn.example.com/corona/bg1.png" />
  <Image ID="bg-sub" Url="https://cdn.example.com/corona/bg2.png" />

  <Mod ID="Corona">
    <CurrentVersion>1.0.0</CurrentVersion>
    <DisplayName Language="zh-CN">日冕</DisplayName>
    <DisplayName Language="en-US">Corona</DisplayName>

    <!-- Mod 页面样式配置 -->
    <Style>
      <!-- Logo：节点文本为图片短 ID，属性定义尺寸、锚点与偏移 -->
      <Logo Width="400"
            Height="160"
            Position="TopLeft"
            OffsetX="24.5"
            OffsetY="16">corona-banner</Logo>

      <!-- 控件与文本样式 -->
      <Controls>
        <!-- 主标题文本 -->
        <PrimaryLabel>
          <Color Format="CSS">#FFFFFFFF</Color>
          <FontSize>20</FontSize>
          <FontWeight>700</FontWeight>
        </PrimaryLabel>

        <!-- 副标题文本 -->
        <SecondaryLabel>
          <Color Format="CSS">#FFFFFFAA</Color>
          <FontSize>14</FontSize>
          <FontWeight>400</FontWeight>
        </SecondaryLabel>

        <!-- 主操作按钮 -->
        <PrimaryButton>
          <BackgroundColor Format="CSS">#FFCC00</BackgroundColor>
          <BorderColor Format="CSS">#FFDD33</BorderColor>
          <BorderWidth>1.5</BorderWidth>
          <Color Format="CSS">#000000</Color>
          <FontSize>16</FontSize>
          <FontWeight>600</FontWeight>

          <!-- 悬停态 -->
          <Hover>
            <BackgroundColor Format="CSS">#FFD633</BackgroundColor>
            <BorderColor Format="CSS">#FFEE66</BorderColor>
          </Hover>

          <!-- 按下态：独立声明，绝不自动继承 Hover 的黄色 -->
          <Active>
            <BackgroundColor Format="CSS">#E6B800</BackgroundColor>
            <BorderColor Format="CSS">#CCA300</BorderColor>
          </Active>
        </PrimaryButton>

        <!-- 次要按钮：演示 ARGB 格式与半透明白色边框 -->
        <SecondaryButton>
          <BackgroundColor Format="ARGB">#80202226</BackgroundColor>
          <BorderWidth>0</BorderWidth>
          <Color Format="CSS">#F0F0F0</Color>
          <FontSize>14</FontSize>
          <FontWeight>400</FontWeight>
          <Hover>
            <BackgroundColor Format="ARGB">#A033373D</BackgroundColor>
            <BorderColor Format="CSS">#FFFFFF80</BorderColor>
            <BorderWidth>1</BorderWidth>
            <Color Format="CSS">#FFFFFF</Color>
          </Hover>
          <Active>
            <BackgroundColor Format="ARGB">#C01A1C1E</BackgroundColor>
            <BorderColor Format="CSS">#FFFFFFA0</BorderColor>
          </Active>
        </SecondaryButton>
      </Controls>

      <!-- 背景配置：按 Schema 顺序先 Image 列表，后 Color 与 SecondaryColor -->
      <Background Random="true">
        <Image>bg-main</Image>
        <Image>bg-sub</Image>
        <Color Format="CSS">#121417E6</Color>
        <SecondaryColor Format="CSS">#1C1F24F0</SecondaryColor>
      </Background>
    </Style>
  </Mod>
</Metadata>
```

### 4. Vue 映射规范（Vue 与 CSS 映射）

元数据发布或序列化给前端消费时，遵循以下命名与渲染映射规则：

#### (1) 命名规范转换
- **XML 节点与元素**：PascalCase（例如 `PrimaryButton`、`BorderColor`、`BorderWidth`、`BackgroundColor`、`FontSize`、`FontWeight`）。
- **Vue 前端消费对象**：camelCase（例如 `primaryButton`、`borderColor`、`borderWidth`、`backgroundColor`、`fontSize`、`fontWeight`）。
- **最终渲染 CSS 属性**：kebab-case（例如 `border-color`、`border-width`、`background-color`、`font-size`、`font-weight`）。

#### (2) 语义字段映射与单位
- `Background.Color` 映射为页面的底层背景色，`Background.SecondaryColor` 映射为内容区域（如信息卡片 Surface）的 `backgroundColor`。
- `Logo.Position` 代表九宫格停靠锚点（TopLeft/Center/BottomRight 等对齐方位），**不是** CSS 的 `position: absolute/relative` 属性；渲染端据此计算容器内的 Flex/Grid 停靠或对齐参数。
- 尺寸、偏移与字号数值单位：数值长度（`Width`、`Height`、`FontSize`、`BorderWidth`、`OffsetX`、`OffsetY`）均映射为带 `px` 单位的 CSS 长度字符串；字重数值（`FontWeight`）映射为无单位整数（如 `400`、`700`）。

#### (3) 交互状态（Hover / Active）与样式注入
- 按钮的 `Hover` 与 `Active` 状态样式，在 Vue 端应通过样式表规则（`:hover`、`:active` 伪类）或 CSS 变量（CSS Custom Properties）进行绑定，**而不是**将其作为嵌套的 style 内联对象直接绑定在元素上。
- **Active 状态解析隔离**：Active 状态中缺省的字段，一律向上解析回落至该按钮的基础样式（Base），绝对不会从 Hover 状态渗漏任何属性。当鼠标松开时，如果指针仍在按钮上方则恢复为 Hover 状态，如果离开则恢复为基础样式。
- **缺省状态逐级兜底**：所有缺省的状态样式，遵循“先当前控件基础样式（Base），后全局主题默认值（Theme）”的原则兜底。

#### (4) 继承与空节点的替换行为
- **Controls、按钮与状态**：若子级声明了空的 `<Controls/>`、空按钮节点或空状态节点，保留继承自 Base 的配置，不冲掉已继承的控件样式。
- **Logo 与 Background**：属于整分类替换机制。如果本地显式声明了空的 `<Logo/>` 或 `<Background/>`，则视为显式清空，完全替换并覆盖 Base 中继承的对应分类。

#### (5) 背景渲染分层
- 前端渲染背景图时，底图放置在独立背景层；半透明的底色遮罩覆盖在底图之上，并使用独立的 `backdrop-filter: blur(...)` 毛玻璃遮罩，**绝对不能**对整个页面容器设置 `opacity`，也**绝对不能**对包含文字和按钮的内容容器直接使用 `filter: blur(...)`，确保文字与所有交互元素始终清晰。

## Alternatives considered

1. **数值透明度（Opacity/BlurRadius） vs. 颜色 Alpha 通道**
   - *备选方案*：在 Style 或 Background 节点增加 `Opacity="0.8"`、`BlurRadius="20"` 字段。
   - *讨论*：在元数据中引入独立的透明度数值会与颜色本身的 Alpha 通道造成重复设置，且模糊效果通常属于客户端主题背景渲染职责，而不是每个 Mod 元数据需要单独控制的属性。因此不增加多余的数值透明度字段，统一通过颜色的 Alpha 通道调节透光程度。
2. **仅支持 CSS 格式 vs. 显式 Format 属性（CSS / ARGB）**
   - *备选方案*：仅支持 CSS 规范（`#RRGGBB` 与 `#RRGGBBAA`），或者根据字符长度自动猜测。
   - *采纳策略*：为每个颜色节点提供可选的 `Format` 属性（`CSS` 或 `ARGB`），且颜色值和 Format 一起替换。这样既保持了以 CSS 规范为默认值，又允许显式指定 ARGB 格式，同时杜绝因自动猜测导致透明通道错位。
3. **保留旧名称别名 vs. 全新统一重命名并升级 SchemaVersion 2.0**
   - *备选方案*：在 XSD 和代码中保留 `LaunchButton`、`Label`、`Brush`、`Thickness`、`IsBold` 别名兼容旧数据。
   - *采纳策略*：为了避免长期维护多套名称带来的混淆，决定不再保留旧别名。同时由于升级了控件规范，库内的版本兼容辅助工具在将当前版本提升至 2.0 后，其兼容检查（`IsCompatible`）将对 1.0 的旧数据返回 `false`，促使调用方明确检查版本并完成迁移。

## 修改位置

本次修改涉及以下位置：

1. **Schema 模式定义升级**：
   - 修改 `Metadata/MetadataSchema.xsd` 与 `Metadata/MetadataPublishSchema.xsd`。
   - 完整定义 `StyleType`、`LogoType`、`ControlsType`、`BackgroundType` 及其子元素。
   - 各颜色节点（`Color`、`BackgroundColor`、`BorderColor`、`SecondaryColor`）支持可选属性 `Format`（枚举：`CSS`、`ARGB`，未传时默认为 CSS）。
   - `Background` 元素顺序调整为：先 `<Image>` 列表，后可选的 `<Color>` 与 `<SecondaryColor>`。
2. **新增颜色转换小工具方法（MetadataColor.cs）**：
   - 提供 API `MetadataColor.ToCss(string value, string? format)`。
   - 当 `format` 为 `CSS` 或未传时，6 位或 8 位十六进制直接返回；当 `format` 为 `ARGB` 时，将其转换为 CSS 的 `#RRGGBBAA`（将前置 AA 移至末尾），供消费端统一解析。
3. **元数据继承合并逻辑更新（MetadataInheritance.cs）**：
   - 保持 `Logo` 与 `Background` 的整分类替换行为（子级存在则整项采用子级，子级无则采用 Base）。
   - 更新 `MergeControls`，针对各个控件（`PrimaryLabel`、`SecondaryLabel`、`PrimaryButton`、`SecondaryButton`）及其子状态（`Hover`、`Active`）进行深合并。
   - 合并时执行原始字段覆盖，当覆盖颜色字段时，颜色值和 Format 一起替换。
4. **构建校验与关联检查（MetadataBuilder.cs）**：
   - 增强构建校验 `ValidateHard` 与 `SchemaValidator.ValidateFile`：
     - 校验 `Style` 引用的所有图片短 ID（Logo 文本、Background 的 Image 文本），即使该 Mod 没有声明 `Packages` 或 `Posts`，也严格校验引用的 ID 确实在顶层登记为 `Image`（引用 Markdown 报错类型不符）。
     - 校验所有颜色节点有效性：当 `Format="CSS"`（或未传）时检查是否符合 6 位或 8 位十六进制；当 `Format="ARGB"` 时检查是否严格为 8 位十六进制。
5. **版本兼容性常量提升**：
   - 将 `MetadataSchema.Current` 与 `MetadataBuilder.DefaultSchemaVersion` 提升为 `"2.0"`，版本兼容检查（`IsCompatible`）对 1.0 旧数据返回 `false`。
6. **测试用例与测试数据迁移**：
   - 迁移 `Ra3.BattleNet.Metadata.Tests` 中所有受影响的测试用例与夹具，覆盖空的 `<Style/>` 与空分类、显式 0 值保留、仅含 Style 图片引用的独立 Mod、错误类型引用报错、颜色值与 Format 替换以及 CSS/ARGB 转换。

## Consequences

1. **契约强健性与边界明确**：
   - 元数据协议层不新增独立透明度或模糊参数，使用颜色自带的 Alpha 通道表达透光度。
   - 元数据中的 Hover 与 Active 独立合并；前端按此规则选择状态，消除了数据层将按下状态与悬停状态错误耦合的问题。
2. **版本与破坏性变更影响**：
   - SchemaVersion 升级至 2.0，彻底废弃旧的 `LaunchButton`、`Label`、`Brush`、`Thickness`、`IsBold` 命名，不再保留冗余的兼容别名。
   - 库内的版本兼容辅助工具在检查 1.0 旧数据时会返回 `false`（不兼容），使用本库的客户端必须明确升级并检查 SchemaVersion。
3. **图片引用完整性受控**：
   - 构建阶段排查所有样式引用的图片短 ID，杜绝了悬空引用或跨类型引用（例如将 Markdown 填入 Logo）发布上线的风险。
