# 技术债跟踪

只记已经确认的缺口，写清“现在怎样、为什么不改、改的时候注意什么”。销项时删掉整行，并在提交信息里说明。

| # | 缺口 | 现状与风险 | 下一步 |
|---|---|---|---|
| 1 | `MetadataClient.cs` 约 1700 行 | 根清单刷新、独立清单预加载、图片三条流程共用一个类，改一处要读全文件 | 按流程拆成三个部分类或内部协作类，公开签名保持不变 |
| 2 | `MetadataDiskCache.cs` 约 730 行 | 布局、校验、暂存、提交混在一起；地址归属规则只在一处，改动容易踩 Windows 路径不区分大小写 | 先抽“地址到路径”的纯函数并加表驱动测试，再动其余逻辑 |
| 3 | `MetadataBuilder.cs` 775 行 | `Build` 与 `ValidateHard`、清单语义检查、显示名校验挤在一个类；报错顺序隐式依赖调用顺序 | 按阶段拆成独立校验器，每段返回错误列表由入口汇总 |
| 4 | XSD 里的 `Manifest/SubManifest` 无人读取 | 作者可以合法写出它，构建器不校验、库不解析、客户端不认 | 要么补齐读取与校验，要么从模式中删除；两者都要先查客户端是否已依赖 |
| 5 | 字段说明与 XSD 双写 | `.agents/docs/references/metadata-model.md` 手写字段表，XSD 改了容易忘记同步 | 生成一份字段清单到 `docs/generated/`，文档只写含义与取舍 |
| 6 | 没有覆盖率与耗时基准 | 缓存预加载、图片冷读的实际耗时没有数字，回归只能靠感觉 | 加一个可选基准项目，只在本地跑，不进 PR 门禁 |
| 7 | WebP 结果本地看不到 | 只有 `--webp` 才转换；本地构建产物仍是原图，体积与真实发布不同 | 在发版前跑一次 `npm run build:release` 并抽查 `Output/` |
| 8 | `MarkdownValidator` 无人调用 | 是个公开类，构建器和测试都不调用它；留着让人误以为正文有校验 | 确认没有外部调用后删掉，或真正接进构建校验 |
| 9 | 两条部署线参数靠人记 | EdgeOne 走 `--content-revision`，Cloudflare 走 `npm run deploy`，一旦不一致，产物内容版本不同 | 让两条线都调用同一个脚本入口 |
